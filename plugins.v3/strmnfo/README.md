# STRM媒体信息补全

MoviePilot 整理入库后，自动从 `.strm` 文件名里的技术标签生成同名的
`.strm.nfo`（Kodi streamdetails 格式），供 Emby 的 STRM Probe NFO 插件
读取入库，让媒体播放器显示分辨率 / 编码 / HDR / 音频等媒体信息。

**全程只读文件名，不访问云盘、不下载任何文件。**

## 怎么用

1. 插件配置里打开**启用插件**，监控目录填 MoviePilot 容器内能看到的
   `.strm` 目录（默认 `/media/Link`），点保存；
2. 第一次使用时打开**立即运行一次**，保存后 3 秒开始全量扫描，把已有的
   `.strm` 一次性补齐；
3. 以后每次整理完，插件自动给新入库的 `.strm` 生成 nfo；每 6 小时还会
   全量扫描一次兜底。也可以发 `/strmnfo_scan` 命令手动触发一次全量扫描。

## Emby 侧（必须做，否则 nfo 不生效）

1. Emby 装好 STRM Probe NFO 插件（4.10.1.0+），在它的设置里**选上所有含
   `.strm` 的媒体库**并保存；
2. Emby 仪表板 → 计划任务 → 运行 **Apply pending .strm.nfo sidecars**，
   把安装前就已入库的条目补读进去；
3. 之后新增的 nfo 由 Emby 媒体库实时监控或 STRM Probe NFO 的每日定时任务
   自动处理。完成后在 Emby 里打开一部片子，看媒体信息是否显示正常。

## 两种取数模式

- **文件名模式（默认）**：只读 `.strm` 文件名里的技术标签，不访问网络、
  不下载任何文件。分辨率是标称值（`2160p` → `3840x2160`），码率/时长
  只能靠文件名里显式写明。
- **探测模式（推荐，配置里打开「探测真实参数（ffprobe）」）**：读 `.strm`
  里的 URL，用 HTTP Range **只拉约 900KB 头部**交给 ffprobe，拿到真实值：
  精确宽高（如 `3840x1608`）、真实视频码率、帧率、HDR/SDR/DV、色深、
  色彩原色/传递函数/色彩空间、像素格式、Profile、每条音轨的编码/声道/
  声道布局/码率/语言/采样率/标题/默认标记、字幕轨标题/默认标记、总码率、
  体积、真实时长。
  探测失败的条目（URL 失效、超时、无 ffprobe）自动回退文件名模式，不会写坏 nfo。
  单次扫描最多探测 `probe_limit` 个（默认 200），避免一次把整库都拉一遍头部。
  开着「每文件夹只探测一个」时，同一文件夹每轮只探测第一个需要生成的文件，
  其余走文件名模式——一轮下来每个剧只花一次探测。
- **只识别文件名（配置里打开「只识别文件名（不探测）」）**：完全不探测、
  不发任何网络请求，全部走文件名模式，上面探测相关的开关全部被忽略。
  适合 `.strm` 链接打不开、或者不想让插件访问任何服务的人。

## 能识别什么

文件名模式：分辨率（2160p/1080p 等，也认文件名里显式的 `3840x2160`）、
视频编码（HEVC/H.264/AV1 等）、HDR（DV 优先于 HDR10/HLG/SDR）、多轨音频
（TrueHD/DTS-HD MA/DDP/EAC3/AC3 等，每轨各自带声道）、声道（5.1/7.1，
接受 `DDP5.1` 这种无分隔写法）、帧率、码率、音轨语言、字幕。

探测模式：上面这些全部按真实探测值写，另外多写 bitdepth / pixelformat /
profile / colourprimaries / colourtransfer / colourspace / 音频 bitrate 与
samplerate / 音轨 title 与 channellayout 与 default / 字幕 title 与 default /
fileinfo 的 totalbitrate 与 size。**这些扩展字段 Kodi 和 Emby 原生不解析**，
要 Emby 侧插件扩展解析才会显示在播放器里；不扩展时它们只是无害的附加信息，
标准字段照常生效。

## 注意

- 文件名里没有任何技术标签、又没开探测模式的文件生成不了（比如只有
  片名 + 集数）；开了探测模式就能靠真实探测补上。
- 探测模式需要容器内有 `ffprobe`。MoviePilot 官方镜像自带 ffmpeg；
  如果是精简镜像，可设环境变量 `FFPROBE_PATH=/path/to/ffprobe`。
- 默认不覆盖已有 `.strm.nfo`，重复运行安全；想重新生成就打开
  「覆盖已有 .strm.nfo」。
- 插件详情页能看到累计生成 / 跳过 / 无法解析 / 失败的统计和失败文件列表。
